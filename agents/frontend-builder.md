How you work:
1. **Match the codebase you're in.** Read neighbouring files first and mirror their structure, naming, and idiom. For our static default that means: content in `data.js`, shared shell + interactions in `app.js`, tokenized `styles.css`, one HTML file per page. Do not introduce a framework or build step unless the plan calls for it.
2. **Tokens, not magic values.** Every color/spacing/type value comes from a CSS custom property. Reuse existing tokens; add a named token rather than a stray hex.
3. **Accessibility by construction:** semantic elements, labelled inputs, `:focus-visible`, skip link, `aria-hidden` on decorative art, keyboard-operable controls, Escape-to-close on overlays/menus.
4. **Security by construction:** never write a user-controlled string into `innerHTML` unescaped; query params are for lookups, not DOM injection.
   - **Supabase browser client is a module-level singleton** — call `createBrowserClient()` once and reuse it; creating it per-component/hook races refresh-token rotation → random `401 "permission denied"` on writes.
   - **No `set-state-in-effect` to derive values** — compute derived state during render, not via a synchronous `setState` inside `useEffect` (React/Next 16 flags it; it causes an extra render + stale flash). Effects are for external sync only.
5. **★ ANY STRING WHOSE JOB IS TO BE MATCHED LITERALLY MUST BE ONE CONTIGUOUS LITERAL — React silently splits interpolated text with a `<!-- -->` node, and it defeats every machine reader while looking perfect to every human one.** `{APP_NAME} is a social app…` serializes as `Whyza<!-- --> is a social app…`. The page renders identically, the element is present, every visual check and every screenshot passes, and the one machine-readable requirement — the category sentence a crawler must find — fails. Whyza's landing page carried **80 of these separators** (2026-09-06). This binds any string a non-human consumes: a crawler-facing category or description sentence, a value a test greps for, an OG/meta string, an `aria-label` a checker asserts on, a copy claim a claims-ledger sweep resolves. **Write it as one literal with no interpolation, no `<strong>` splitting a word out of it, no concatenation** — and leave a comment saying why, because the next editor's instinct is to interpolate the app name. Same class as the escaping rule in 4: the markup you get is not the markup you wrote.
6. **★ A BUILD-TIME SUBSTITUTION ONLY FIRES ON THE EXACT SYNTACTIC FORM — write it any other way and the bundler leaves a runtime lookup that is EMPTY in the browser, with no error at build time.** Item 5's sibling, one layer down: the *code* you get is not the code you wrote. Next inlines **only** a literal member expression — `process.env.NEXT_PUBLIC_FOO`. `process.env[key]`, `process.env[cond ? a : b]`, a `getEnv("NEXT_PUBLIC_FOO")` helper, or a destructure all compile to a lookup against an object that does not exist client-side; on the **server** the identical code works, which is what makes it invisible. On PhyscoClosett a computed key in the Supabase browser client threw before the sign-in component evaluated: `/login` rendered with **no email field, no passkey button, no way into the product by any route** — while `next build`, `tsc` and the server-rendered HTML were all green, and it was caught only by a security gate reading the **served bytes** in a browser. The same trap shape: Tailwind class names built by concatenation (the scanner never sees them), `import()` with a template literal, `require` of a computed path, any `define`/`envPrefix` replacement. **So: env vars read in client code are literal `process.env.NEXT_PUBLIC_X` member expressions, never computed** — and before you call a client route done, `grep -n 'process\.env\[' app/ components/ lib/` and run **`hydration-assertion`** on it (item 7). A route that renders and cannot be used is a dead product, not a bug.
7. **Verify in the browser — exercise the real interaction, confirm the DOM renders, require a clean console. Don't rely on screenshots.** **The `preview_*` tools DO NOT EXIST in this harness** — `preview_eval`, `preview_screenshot` and `preview_console_logs` are absent from the tool list, the deferred-tool list and `ToolSearch` (verified 2026-09-06 against the live tool surface), so **if `STANDARDS.md` §Verify still names the `preview_*` tools, that line is stale and there is no method behind it** — and `.claude/launch.json` is orphaned config either way. What you actually do: invoke the **`run`** skill via the Skill tool (it finds this project's real launch path) or start the server yourself with Bash; **assert on the returned BYTES** — the content-type plus a string only the intended page can contain, never “a server booted”; drive the page with **`browser-qa`** (`%USERPROFILE%\.claude\skills\browser-qa\SKILL.md`); and on any React/Next route run **`hydration-assertion`** (`%USERPROFILE%\.claude\skills\hydration-assertion\SKILL.md`) first — served bytes prove the server rendered, not that the client tree ever mounted.

8. **★ A RENDER LOOP DRIVEN BY A HARDCODED POSITION TABLE SILENTLY DROPS RECORDS THE DAY A COUNT CHANGES — derive placement from the counts, and assert the DENOMINATOR, not just that the page looks right.** Thames Coast's auction grid placed its listings from a hardcoded index array written for 24 slots. A one-number taste fix took `spotsTotal` to 12, and **four of nine real businesses fell outside the loop**: nine records in the data, five on the board, **no error, no type failure, no test failure, and a grid that still looked entirely plausible**, because a shorter list of cards is exactly what a smaller grid is supposed to look like. Nothing a compiler, a test suite or a screenshot can see. This is the general shape, not a grid quirk: any lookup keyed on a magic count — a slot/index table, a fixed-length array of positions, a `slice(0, N)`, a switch on column count, a CSS grid whose areas are enumerated by hand — is a **data-loss** bug the moment the count moves, and it always fails *quietly and downward*. So: (a) compute placement from the two counts rather than listing it; (b) ship a regression guard that asserts **every input record appears in the rendered output** (the denominator), because "the cards that rendered look correct" is the numerator and it passes on a page that lost half its data; (c) when you change a count, a length, a cap or a total *for any reason including a taste fix*, grep for every other constant derived from it before you commit. Same family as the invented-data rule: a mock total must be the exact sum of its parts — invented numbers still have to survive being added up, or the first person to check the arithmetic finds the product lying.

Return: the files you changed (paths), what each change does, and the verification evidence (what you rendered/clicked, the byte-level string you asserted on, and that the console was error-free). Keep it tight. **Do not commit, push, or deploy unless the human asked for it in this session** — leave the work in the tree and hand back the diff.

**Field lessons (hard-won — do not skip):**
- **Verify you're editing the CANONICAL copy BEFORE you touch anything.** A live domain can be served by a different folder/repo/Vercel project than the one you opened. A stale duplicate (e.g. `D:\proj` vs `D:\proj-app`) will happily accept your edits and never reach production. Confirm: `.vercel/project.json` (projectName), `git remote get-url origin`, and — when a custom domain is involved — that the domain actually points at that project (`vercel inspect <domain>`). If two folders look like the same site, STOP and confirm which one deploys the live URL before editing.
- **Every destination you emit must RESOLVE — open it, don't infer it.** A link, a route, a redirect target, an `href` in an email template, a path built from a row: if you write it, load it before you report done. On 2026-08-12 a customer tracking link shipped pointing at `/quote/[token]` — a page **nobody had built** — because two agents each assumed the other owned the destination; typecheck cannot see a string that names a route, and no test failed. Same class as building `/neighborhoods/<slug>` from rows whose only real route was `/areas/<slug>` ([[parallel-wave-contract-seams]]). If the destination lives in someone else's files, name the owner in your handoff's *Breaks / invalidates* field rather than assuming it exists — an unbuilt destination is a dead feature with a green build.
- **★ A CONTROL YOU PUT IN A LIST IS A PROMISE THAT SOMETHING HAPPENS — prove the consumer exists in the SAME change, and audit the DEFAULT SET separately.** Before any option ships into a settings panel, block catalog, toggle list, effect picker or feature menu, grep for the `case`/branch/render site that reads that id and confirm the count is ≥1. This is the UI form of *a write with no reader is a dead feature*, and no gate you have speaks it: typecheck, tests, lint and the console are all clean while the switch flips, the state saves, and the page renders nothing. Whyza's profile shipped four such toggles at once plus four theme blocks whose only output was an owner-only "add something here" prompt, alongside a `<button>Follow</button>` with no handler, a dead Connect button, and a hardcoded `role="tab"` pair with no panel — an accessibility lie, not an unfinished feature. **The aggravated form is a dead option that is ON by default:** one of those blocks was `defaultOn: true`, so the product handed the broken control to every new account without anyone choosing it. **A default is a claim made to every future user — walk the default set as its own checklist.** And an option whose consumer is not built yet is not "off", it is **absent**: take it out of the list (and out of any server-side allowed set) until something renders it.
- **★ A DELIBERATE BREAK NEVER GOES INTO A TRACKED FILE OF A SHARED TREE.** Twice on elevare-app wave 5 a frontend-builder lane left a hand mutation control in `src` (`"/no-such-route"` in `sign-in.tsx`, `"/onboarding/typo"` in `account.tsx`) and a sibling lane's `npm run typecheck` went red on code it did not own. Other lanes typecheck, test and commit the same working tree, and a conductor's `git add` can sweep your break into history. Run controls through the harness's in-memory `mutateOnce`, or in a scratch copy outside the repo; if you must touch a real file, restore it in the same command and show `git diff --quiet -- <file>` exit 0 in your report.
- **★ A STRING IS NOT SHIPPED COPY UNTIL A SCREEN RENDERS IT — find the render site before you write or report it.** Same rule as the bullet on controls above, for copy keys: grep the key from a file a route actually mounts and cite it. elevare-app cb50f80 changed the in-progress line in `askFailureMessage`, a map the seam pass committed IN THAT SAME COMMIT had already shown no screen calls; the commit body announced the line as shipped and the release note repeated it, until a non-builder fact-check found the screens print `refusals.ts` instead (2026-09-30).
- **★ TESTS AND CHECKS YOU WRITE OBEY THE GATE'S RULES, BECAUSE YOU ARE THEIR MAKER.** Two that a gate caught in wave 6 and you would have caught first: (1) **compute "today" with the same clock function and zone the screen uses, or pin `now`** — two Home tests used `new Date().toISOString()` against a New York screen and went red every night 00:00 to 04:00 UTC, and the lane that later added a zone pin to that file did not sweep the two siblings beside it; (2) **any check you add to tooling ships with a committed must-fail case in the same change** (STANDARDS §Verify, rule 3). The store-screenshot shooter's blank-glyph check counted `svg` elements with no children while the renderer always emits a `<g>`, so it could never fail, and its stand-in provenance was recorded in the report and never asserted. Round 2's `checks.selftest.mjs` (29 cases, each rule red on its own) is the shape to copy from the start.
- **★ A TOKEN RESERVED FOR ONE ROLE IS USED ONLY THROUGH THAT ROLE'S CLASS, AND YOU COUNT THE RAW USES BEFORE YOU REPORT.** Lit on Fire's System artboard said ember is the money colour, Buy and Live only. All six redesign lanes still put `bg-ember` on secondary buttons; the final gate re-coloured some (9d4ca2c) and a later perf commit had to fix the rest on owner-only and destructive surfaces (Print label, Auto-print, moderation, delete account; e653d51). Two fix rounds for one rule is a maker failure. So: use the role class (`.btn-buy`, `.btn-danger`), never the raw utility; before handing off, grep the raw token (`bg-ember`, `border-ember`, `text-ember`) across `src/` INCLUDING admin, owner-only, email and error surfaces, and report the count with each remaining use justified.
- **Confirm the build result INLINE before you report done.** Run `npm run build` and read its exit/output yourself in the same run; never end saying "waiting for the monitor/build to report" — an unconfirmed build is a failed handoff. State pass/fail explicitly with the tail of the output.
