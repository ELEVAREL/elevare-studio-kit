# Offline Ed25519 signed-license tokens (issue in the cloud, verify offline, machine-bound, tiered caps) + a golden-token wire-contract fixture

**When to reach for it:** any buy-once / self-hosted / desktop product where the app runs on the customer's own machine and must enforce paid tiers **without phoning home** after a one-time activation — a licensed desktop app, an on-prem tool, a "buy the license, run it anywhere, works offline" product. This is the licensing spine: a cloud signer, an offline verifier embedded in the app, and a **golden fixture that pins the two together** so the TS-signer and Python-verifier can't silently drift. Pairs with [`../buy-once-fulfillment/stripe-buyonce-fulfillment.md`](../buy-once-fulfillment/stripe-buyonce-fulfillment.md) (the purchase that mints the license) and ships inside [`../desktop-native-app/pywebview-pyinstaller-boilerplate.md`](../desktop-native-app/pywebview-pyinstaller-boilerplate.md).

**Assumes / adapt:**
- **Ed25519, sign in the cloud, embed only the PUBLIC key in the app.** The hub signs with `LICENSE_SIGNING_PRIVATE_KEY_PEM` (never shipped); the app verifies against `license_public_key.pem` bundled into the frozen build. Token format: `b64url(JSON(payload)) + "." + b64url(sig)`, signed over the **b64url data string's ASCII bytes** (not the raw JSON, not the decoded payload). Keep both sides byte-identical or the golden test goes red.
- **Verification is fail-closed and only catches EXPECTED failure modes narrowly.** Catch `InvalidSignature / ValueError / KeyError` → return `None`; a *surprise* exception type is logged once-per-type then still returns `None`. No token, no public key, malformed framing → `None`. Never let a verification error read as "valid."
- **Bind to a machine fingerprint, but tolerate hardware drift.** Fingerprint = `sha256(hostname | primary-MAC | arch | disk-serial)[:32]` — a *hash*, so the license file never exposes raw hardware ids. The token's `fp` claim must match (or be null). Because fingerprints change on hardware swaps, the cloud allows a small number of re-activations — don't hard-fail a legitimate customer who upgraded their PC.
- **Three-tier resolution, in order:** (1) a stored signed machine-bound token = paid tier; (2) a time-limited full **trial** from first-run epoch; (3) a forever-free floor tier. Make the paywall a *feature* (e.g. AI off on free), not a nag — the free tier stays useful. `current_license()` returns caps + the gated-feature flag; enforcement points (camera cap, feature gate, UI pill) read it.
- **Write the token/key atomically (`temp + os.replace + fsync`).** A crash or full disk mid-write must never leave a truncated token — that would silently downgrade a paying customer to Free. Same for the `install.json` first-run marker (which anchors the trial clock).
- **Tier auto-refresh without re-entry.** A background thread (start + every ~2h) and an on-settings-open call re-activate with the *stored* key to pull the current tier — this is how a Home→Business upgrade reflects with no customer action. Idempotent (same machine → no activation consumed), non-fatal (keep the existing token if offline). Contain *every* exception in the refresher tick or one bad cycle kills tier-sync for the process lifetime.

## The golden-token wire-contract fixture (the part that pays off later)
The signer is TypeScript in the cloud; the verifier is Python in the app. Nothing in either type system stops them drifting on payload keys, base64url variant, what bytes get signed, or the `data.sig` framing — until a real customer's token silently fails to verify. Pin it:
- A **build-time Node script** (`make-golden-token.mjs`) replicates the cloud signer **byte-for-byte** with a throwaway TEST keypair, writes `golden_token.txt` + `golden_public.pem` into the engine's test fixtures, and self-verifies before writing.
- A **pytest** (`test_token_contract.py`) runs the app's *real* verifier against that committed token and asserts the **exact** decoded payload (extra/missing/renamed keys fail). Plus: the same token must be **rejected by the production public key**, a re-serialized payload with the original signature must fail (proves you verify *bytes*, not semantics), and a tampered claim must fail.
- If either side changes construction, the test goes red and you regenerate deliberately. This one fixture is what makes "the TS signer and Py verifier agree" a *test*, not a hope. (Cf. memory `parallel-wave-contract-seams` — a green build hides broken cross-language contracts; pin the wire shape with a fixture.)
