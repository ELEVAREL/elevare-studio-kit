# ops-systems/ — software that RUNS a business (machines, bookings, tills, staff)

The operational-systems domain: a company needs software to **operate** — not to market. The car-wash class of job: bookable bays/chairs/machines, a till that keeps working when the network dies, staff running the day from a shared device, hardware the software has to drive. Seeded 2026-08-29 from studio lessons (chiefly the Fanta salon kiosk/booking work — the live bugs are cited inside each pattern); these are **skeletons a first real job hardens**, not battle-tested drop-ins yet.

Shared spine across all five: **the database is the source of truth and the enforcement point** (exclusion constraints, unique idempotency keys, RLS/definer RPCs, audit rows in the same transaction) — application-level checks are UI hints. And every money/machine loop gets a **reconcile cron** as its safety net, because webhooks and networks fail.

| Pattern | When to reach for it |
|---|---|
| [`scheduling-and-capacity.md`](scheduling-and-capacity.md) | Bookable resources (bays, chairs, machines) with capacity, duration + buffer, staff assignment. Double-booking prevention at the DB level — a gist **exclusion constraint** on `(resource_id, tstzrange)` with a cancelled-releases-the-slot `where` clause — never an app-level check-then-insert. Walk-ins are bookings too (one ledger, same arbiter). |
| [`booking-engine.md`](booking-engine.md) | The customer-facing half: slot generation as a pure function of capacity, deposits (10% house default / flat when prices vary), cancellation windows with refund eligibility encoded in data (Fanta's 48-hour refundable-deposit rule is the live example), reminder + no-show flow with DB-level email dedupe. Carries the idempotency-key-must-cover-the-whole-request bricking lesson + the reconcile cron. |
| [`pos-offline-till.md`](pos-offline-till.md) | The till keeps selling when the network dies: local outbox with client-minted UUIDs, sync on reconnect, idempotent server upserts on `client_request_id`, and **cash vs card recorded AT WRITE TIME** (live lesson: Fanta's kiosk stored no payment method — the split is permanently unrecoverable, guessed by date cutover). End-of-day reconciliation as a first-class screen. |
| [`staff-roles-console.md`](staff-roles-console.md) | Operator console on a shared device: role-split views (owner sees money, staff sees their queue) enforced by RLS/definer RPCs, PIN short-auth **re-verified server-side in the same request as the write it gates** ("gate the action that WRITES, not the one that collects"), per-action audit trail, and a designed degraded mode per role. Plus the kiosk UI traps (no portalled dropdowns; diagnose dead controls from the data). |
| [`equipment-control-loop.md`](equipment-control-loop.md) | Software drives machines (wash bays, locks, signage): command queue with acknowledgement + aggressive expiry, poll-as-baseline with events as accelerant (events get lost — reconcile on poll), machine-offline as a designed mode that pulls the resource from the slot generator, server-stamped time (never the machine's clock), and PIN-gated audited **manual override as a first-class feature**. |

**Pairs with:** `admin-dashboard/` (the owner's private back-office over the same data), `ecommerce-supabase-stripe/themed-inapp-payments.md` + `stripe-connect/` (the payment rails under the deposits/till), `personal-pwa/offline-first-vendored-supabase-sync.md` (the outbox mechanics in full), `supabase-nextjs-pwa/pwa-auto-update-install.md` (keeping the installed kiosk PWA current — see memory `[[pwa-never-sees-a-deploy]]`).
