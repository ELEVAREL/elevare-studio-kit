# Self-contained HTML/GSAP/Canvas ad → deterministic MP4 (puppeteer element-screenshot, no React rewrite)

**When to reach for it:** you have a **single-file HTML/CSS/JS ad** (GSAP timeline + live Canvas/WebGL + procedural Web-Audio SFX — the [[animated-ad-production]] artifact) that already runs and looks right in a browser, and you need a **frame-accurate MP4** of it for FB/IG **without** re-authoring it as Remotion/React. This pipeline screenshots the real running ad frame-by-frame against a deterministic virtual clock, then muxes music + baked SFX. It renders **N ads cheaply** when they share a fixed beat skeleton (only the frames differ; one audio bed is reused). Distinct from [`remotion-mp4-ad-pipeline.md`](remotion-mp4-ad-pipeline.md) (author-in-React); reach for THIS when the ad already exists as self-contained HTML and you don't want to rebuild it.

**Assumes / adapt:**

- **The deterministic render API is the whole trick.** A Canvas/GSAP ad advances on wall-clock (`performance.now()` / `requestAnimationFrame`), so a naive screenshot loop captures whatever frame happened to be on screen — non-deterministic, dropped/duplicated frames, torn audio sync. Fix: expose a render API the renderer drives one frame at a time, and route ALL time through a **virtual clock**:
  - In the ad, put every animation behind `window.__render = { setup(){…}, frame(t, dt){…} }` — `setup()` builds the timeline paused; `frame(t,dt)` seeks GSAP (`tl.time(t)`), steps the canvas sim by `dt`, and draws exactly one frame at absolute time `t`.
  - Add a `__VT` (virtual-time) fallback that overrides `performance.now()` and `Date.now()` to return the renderer-supplied `t` whenever render mode is active, so any code still calling `performance.now()` stays in lockstep with the seek. Keep the normal rAF loop for live/browser playback; render mode ignores it and calls `frame()` itself.
  - Gate SFX in render mode (they're baked separately from the same beat times — see below), so the visual render never depends on audio.
- **render.mjs — puppeteer-core + SYSTEM Chrome, element screenshots.** Launch `puppeteer-core` against the machine's real Chrome (`executablePath: "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe"` — same reason as Remotion: the bundled/managed browser download is blocked on this machine). Set viewport to the ad's exact pixels (1080×1920), `deviceScaleFactor: 1`. For each frame `i` of `fps*duration`: `t = i/fps`, `await page.evaluate((t,dt)=>window.__render.frame(t,dt), t, 1/fps)`, then screenshot the **ad element** (not `page.screenshot` full-page — clip to the ad's bounding box for exact dims) to `frames/f%05d.png`. Deterministic because every frame is an explicit seek, never a timing race.
- **finalize.mjs — inline assets by split/join, never `String.replace`.** Author the HTML with placeholder tokens (`__FONTN__`, `__MUSIC__`, `/*__GSAP__*/`, …) and inject font/music/GSAP/CustomEase base64 with `h.split(tok).join(val)` — `String.replace` mangles the `$` sequences in base64/GSAP source. Append the render-mode CSS (freeze animations, hide the play poster) in the same pass. (Same rule as [[animated-ad-production]].)
- **Audio is baked ONCE and reused across the slate.** `bake-audio.mjs` renders the procedural Web-Audio SFX offline (OfflineAudioContext) to a wav/mp3 at the exact beat times; `mux.sh` runs `ffmpeg` to combine `frames/*.png` + the music bed + the baked SFX into the final MP4. **The reuse win:** hold a FIXED beat skeleton across every ad in the campaign (e.g. transitions at 3.05 / 5.7 / 9.6s, the payoff accent at 7.55s). Then all N ads share ONE baked audio bed — only the PNG frames differ per ad, so adding the 6th ad costs a frame render, not a new sound design pass. Design the beat skeleton first; make each ad's motifs land on those timestamps.
- **Parallelize the slate by file.** Build the shared `ad-template.html` (the render-API engine + the beat skeleton) once, then fan out one motion-ad-director subagent per ad variant, each owning its own `ad-<x>.html` off the template (distinct kinetic motif, same beat times). Renders are independent and run concurrently. (Standard parallel-wave rule — disjoint file ownership; PLAYBOOK.)

**Gates that MUST run on the rendered MP4, not just the browser ad:**
- **No empty mid-transition frame.** Any sweep/wipe/split-screen transition that moves content off-screen can leave a near-empty frame at the seam — invisible at 60fps live but a jarring flash in the MP4 (bit ad-E's split-screen sweep ~8.4–8.7s). Scrub the rendered frames across every transition window and confirm the incoming content is already on-screen before the outgoing leaves (crossfade / overlap, never a bare seam). This is a per-frame check the live-playback QA misses.
- **Honesty on every on-screen number.** If the brief gives a TOTAL, do not fabricate a line-item breakdown to sum to it (ad-E invented $420/$350/$260/$150). Show labels/names, or real sub-figures only. Claim–reality parity (STANDARDS).

**Pipeline files (reference implementation, scratchpad of session 587b04e4):** `ad-template.html` (render-API engine + beat skeleton) → `finalize.mjs` (token inject + render CSS) → `render.mjs` (puppeteer-core + system Chrome, element screenshots) → `bake-audio.mjs` (offline SFX bake) → `mux.sh` (ffmpeg frames + music + SFX). First proven on the 6-ad Elevare Launch Kit slate ([[launch-kit-animated-ad]]).

## Hard-won additions (Fanta 5-reel slate, 2026-07-15)
- **Frame 0 is a lie:** GSAP `tl.set(..., 0)` states do NOT render when you seek exactly `t=0` on the paused timeline — frame 0 comes out as background/chrome only, while `t=0.033` is fully composed. Builders verifying at `t=0.03` will miss it; the full render hits it. Fix at mux: `ffmpeg -start_number 1` (also cleans the loop seam). Check frame f-0000 vs f-0001 on every slate.
- **Automated seam scan** (replaces eyeballing every transition): threshold each frame (`lutyuv y=if(lt(val,200),255,0)` → `signalstats` YAVG = 255×ink-fraction), then flag runs of near-empty frames longer than 0.6s. Calibrate the threshold on a known chrome-only frame (Fanta cream+gold-frame+wordmark ≈ 1.05; content ≥ ~1.5); a too-high threshold false-flags sparse-but-real beats (a lone rolling counter). Script pattern: seamscan.mjs in session 6f7c43de scratchpad\reels.
- **Per-reel SFX without samples or licensing:** synthesize the whole bed in one ffmpeg `-filter_complex` from a beats.json ({t, sfx} events): sine bursts (tick/type/click), `aevalsrc` sweeps (pop/riser), noise+bandpass (whoosh), low sine+noise (impact); `adelay`+`amix normalize=0`+`apad`, then `-t DUR` (in-filter atrim after amix mis-measured duration). Vary pitch factor + whoosh band per reel so a slate never shares one bed (mkaudio.mjs, same scratchpad).
- **measure2/rendergen/finalize2 as CONDUCTOR-owned shared tools** with a fixed class-name contract (.eyebrow/.head/.sub/.kv/.menu-line/.daychip/.stream-word...) lets N parallel reel builders self-QA against one safe-area sampler instead of five diverging copies.
